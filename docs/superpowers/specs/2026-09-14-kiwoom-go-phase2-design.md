# kiwoom-go 2단계 — 나머지 REST 227개 설계

작성일: 2026-09-14

1단계 설계: `docs/superpowers/specs/2026-09-14-kiwoom-go-core-design.md`

## 1. 문제

1단계가 코어와 생성기를 세우고 국내주식 시세·차트·종목정보 **77개**를 냈다. 남은 REST
**227개**(국내 106 · 미국 121)를 같은 생성기로 낸다.

그런데 그대로 이어 붙이면 안 되는 것이 하나 있다 — **2단계에는 돈이 움직이는 API 가 20개
들어온다**(국내 주문 8 · 신용주문 4 · 미국 주문 5 · 환전 3). 지금 전송 계층은 401 을 받으면
토큰을 새로 받아 **한 번 더 보낸다.** 1단계는 전부 읽기라 안전했지만, 주문에서는 첫 요청이
서버에 닿아 체결됐는데 응답만 401 로 보이면 **같은 주문이 두 번 들어간다.**

## 2. 목표

- 나머지 REST **227개**를 생성해 동작시킨다.
- **이중 주문 경로를 없앤다.**
- 패키지가 25개로 늘어도 사람이 손으로 관리하지 않게 한다.

### 목표 아님

- **실시간 WebSocket 23 + 조건검색 8** — 프로토콜이 다르다. 3단계다.
- **`ka10173` 의 `Object`·`List<Map>`** — 3단계 범위이고, 1단계 전수 스캔에서 그 API 하나뿐임이
  확인됐다(1단계 설계 §4.2). 2단계 227개는 생성기가 그대로 처리한다.
- **OAuth 접근토큰 폐기** — 토큰은 만료로 정리된다. 필요해지면 한 함수다.
- **긴 설명의 한 줄 주석 재배치** — 1단계 설계 §4.3 에 적은 대로 여기서도 미룬다. 227개를
  생성한 뒤 실제로 얼마나 거슬리는지 보고 3단계에서 정한다.

## 4. 전송 계층 — 재시도를 걷어낸다

`internal/transport` 의 `Do` 에서 **401 재시도를 없앤다.** 401 을 받으면 토큰만 버리고
에러를 돌려준다.

```
현재:  401 → Invalidate → 같은 요청 한 번 더 → 두 번째도 401 이면 에러
바뀜:  401 → Invalidate → 에러
```

실패한 호출은 사용자에게 에러로 돌아가고, **다음 호출이 새 토큰을 받으므로 스스로
회복된다.** 같은 주문이 두 번 들어갈 길이 사라진다.

### 왜 카테고리로 가르지 않나

"주문 계열만 재시도에서 뺀다" 는 방법도 있다. 그러나 **어떤 API 가 돈을 움직이는지 스펙이
알려주지 않는다.** 메뉴 이름으로 추측해야 하는데, 계좌 카테고리에 취소·정정이 섞여 있으면
조용히 놓친다. 규칙이 하나면 틀릴 자리가 없다.

대가는 401 한 번에 호출 한 번이 실패하는 것이다. 토큰은 **만료 60초 전에 미리 갱신**하므로
(1단계 §8) 실제로는 거의 나지 않는다.

형제 `toss-go` 는 재시도를 GET·멱등키 있는 쓰기로 한정한다. 키움에는 멱등키가 없으므로
더 보수적으로 간다.

### 테스트

기존 `TestDo_401이면_한번만_재발급한다`·`TestDo_401이_계속되면_포기한다` 를 다음으로 바꾼다.

- `401 이면 토큰을 버리고 에러를 돌려준다` — 서버 호출이 **정확히 1회**, `Invalidate` 1회,
  반환은 `*APIError{StatusCode: 401}`
- `401 뒤 다음 호출은 새 토큰으로 나간다` — 자기 회복을 확인

## 5. 하위 클라이언트를 생성물로 돌린다

패키지가 25개가 되면 `client.go` 를 손으로 쓰고 루트에 배선하는 일이 25번 생긴다.
**"패키지를 만들고 배선하는 것을 깜빡" 하는 실수가 반드시 난다.** 그래서 생성기가 찍는다.

- `domestic/<pkg>/client.go` · `overseas/<pkg>/client.go` — `DO NOT EDIT`
- 루트 `subclients.go` — `DO NOT EDIT`

```go
// subclients.go (생성물)
type Clients struct {
	DomesticQuote *quote.Client
	// … 25개
}

func newClients(tr *transport.Client) Clients { … }
```

손으로 쓴 `Client` 가 `Clients` 를 **임베딩**한다. 그러면 `c.DomesticQuote` 접근이 1단계와
똑같이 동작하고, 3단계에서 패키지가 더 늘어도 사람이 할 일이 없다.

1단계의 하위 클라이언트 3개도 생성물로 바뀐다 — 손으로 쓴 파일이 21개에서 18개로 준다.

**손으로 쓴 `client.go` 에서는 `DomesticQuote`·`DomesticChart`·`DomesticStock` **필드를 지우고**
`Clients` 임베딩으로 대체한다. `NewClient` 의 반환부도 `Clients: newClients(tr)` 로 바꾼다.
사용자 코드(`c.DomesticQuote.…`)는 임베딩 덕에 **그대로 동작한다** — 외부 모듈 빌드로 확인한다.

**필드 이름은 `<시장><카테고리>`** 다(`DomesticQuote`·`OverseasRanking`). 시장이 다르면
카테고리가 겹쳐도(`ranking` 이 양쪽에 있다) 구분된다.

## 6. 카테고리 → 패키지 이름표

**이것만은 지어낸다.** API 이름은 공식 영문명을 쓰지만(1단계 §6.1) **패키지 이름은 스펙이
주지 않는다.** `기관/외국인` 처럼 슬래시가 든 것도 있어 자동 변환은 불가능하다.

생성기에 25줄짜리 표로 명시하고, **표에 없는 카테고리를 만나면 멈춘다.** 3단계에서 새
카테고리가 들어올 때 조용히 빠지지 않게 하려는 것이다 — 이름표 없는 API 에서 멈추는 것과
같은 규율이다.

## 7. 생성은 두 번에 나눠 커밋한다

227개를 한 커밋에 넣으면 뭔가 틀렸을 때 어디인지 좁히기 어렵다. **국내 106 → 미국 121**
순으로 두 커밋으로 나눈다. 생성기는 한 번에 다 돌리되 커밋만 가른다.

## 8. 검증

| 무엇 | 어떻게 |
|---|---|
| 카테고리별 개수 | 22개 각각이 §3 표와 맞는지 |
| **재생성 결정성** | 다시 돌려 `git status` 가 비는지 |
| 컴파일·포맷 | 루트·`tools` 두 모듈 `build`·`vet`·`test`·`gofmt` |
| **외부 모듈 사용 가능성** | 임시 외부 모듈에서 새 패키지를 import 해 빌드. 1단계에서 `internal` 누출로 연속조회가 막혔던 일이 있다 |
| 이름 충돌 | 생성기의 중복 가드가 227개에서도 조용한지 |
| 재시도 제거 | 전송 테스트가 "호출 1회" 를 확인하는지 |

## 9. 위험

| 위험 | 대응 |
|---|---|
| 재시도를 없애 일시적 401 이 사용자에게 에러로 보임 | 만료 60초 전 갱신이 대부분 막는다. 이중 주문보다 낫다 |
| 이름표에 없는 카테고리가 조용히 빠짐 | 멈춘다(§6) |
| 227개 중 이름 충돌 | 생성기 가드가 멈춘다. `api_names.json` 337개 값은 이미 전부 유일함이 확인됨 |
| 1단계 하위 클라이언트를 생성물로 바꾸며 회귀 | 기존 테스트가 그대로 통과해야 한다. `c.DomesticQuote` 접근 경로가 바뀌지 않는지 외부 모듈 빌드로 확인 |
| 생성물이 많아 리뷰 불가 | 리뷰는 생성기를 본다. 생성물은 개수·컴파일·재생성 일치로 확인한다 |
